# 本地 LLM 中文创意写作评测题库

107 道题，10 个模块，覆盖文笔、活人感、AI 味与无病呻吟、叙事结构、人物对白、二十多种类型文学、RP / gal 模拟、法学社科论文、超长上下文续航、多语言写作与汉化。每道题都带**评分要点**（含参考答案和典型失败模式），大部分题带**自动指标配置**。附带三个零依赖脚本：批量跑题、自动指标、裁判模型打分。

```
题库/                 10 个模块的题目（Markdown，可直接复制给模型）
评分/通用评分量表.md   十维评分标准、分档、硬伤一票降档规则、手工记分表
评分/AI味与活人感词典.md  AI 味 / 金句体 / 无病呻吟 / 翻译腔 / 活人感的判别依据（含来源）
评分/裁判提示词.md     LLM-as-Judge 模板（judge.py 直接读取）
tools/build_jsonl.py  题库 → tests.jsonl
tools/run.py          对 OpenAI 兼容接口批量跑题（支持多轮、长文件注入、重复采样）
tools/metrics.py      自动指标：AI 味分项、禁词、字数达标、重复率、前后段衰减、多语言 AI 腔
tools/slop_patterns.py AI 味模式库（正则 + 词表，可自行增删）
tools/judge.py        用裁判模型给结果打分并汇总
素材/                 长文本素材（G04 需要你自己放《阿Q正传》全文）
```

## 快速开始

### 1. 生成题目索引

```bash
python3 tools/build_jsonl.py
```

### 2. 跑题

脚本只依赖 Python 3 标准库，适配任何 OpenAI 兼容接口：

```bash
python3 tools/run.py --model qwen3:32b
```

```bash
python3 tools/run.py --base-url http://localhost:1234/v1 --model local-model --ids T-A,T-I,T-D01
```

```bash
python3 tools/run.py --model qwen3:32b --ids T-G --max-tokens 32000 --timeout 7200
```

- 默认地址是 Ollama（`:11434/v1`）；LM Studio 是 `:1234/v1`，llama.cpp server 是 `:8080/v1`。
- `--ids` 按题号前缀筛选；`--repeat 3` 每题跑 3 次（创意写作方差大，强烈建议）；`--tag` 区分同一模型的不同参数；已有结果自动跳过，`--force` 重跑。
- 输出在 `results/<模型名>/`：`.json` 是原始记录，`.md` 是可读对话。`<think>` 推理内容会保留在记录里，但多轮回传时只回传正文。
- **上下文长度**：Ollama 默认上下文很小，G 模块会被静默截断。请先设置 `OLLAMA_CONTEXT_LENGTH`（或在 Modelfile 里设 `num_ctx`）到 32k 以上；llama.cpp 用 `-c`；LM Studio 在加载模型时设置。G01 全程约 35k～45k tokens，G04 输入约 30k tokens。
- G04 需要先把《阿Q正传》全文（公有领域）保存为 `素材/阿Q正传.txt`，脚本会在正文 55% 处自动插入一句"针"；缺文件时自动跳过。

### 3. 自动指标

```bash
python3 tools/metrics.py results/qwen3_32b results/另一个模型
```

每个结果给出：AI 味加权分及分项（对比翻转、金句体、自问自答、身体反应、老牌套话、伪精密意象、无病呻吟、提示词残留、破折号密度）、题目禁词 / 禁用句式命中、字数达标率、8-gram 重复率、前后三分之一的句长与 AI 味对比（看长输出衰减）、多轮题每轮的长度 / 语言 / AI 味。结果写入 `metrics.csv`，终端打印模型对比汇总。

**先校准基线**：拿几本你认可的人类小说或文章跑一下，知道"正常人类文本"在你的阈值下是多少分：

```bash
python3 tools/metrics.py --text 某本小说.txt 另一本.txt
```

```bash
python3 tools/metrics.py --text 某个输出.txt --show
```

`--show` 会列出每一处命中的原句，方便确认是不是误判。模式库在 `tools/slop_patterns.py`，可以按你的口味增删。

### 4. 裁判模型打分（可选）

```bash
python3 tools/judge.py results/qwen3_32b --judge-base-url https://你的接口/v1 --judge-model 裁判模型 --api-key KEY
```

- 裁判模型应**强于**被测模型，且不要让被测模型给自己打分。
- 输出 `judge/<题号>.json` 与 `judge_summary.csv`，终端按模块和十个维度汇总。
- 单题总分 = 十维均分 × 0.5 + 专项分 × 0.5；出现硬伤时专项分不超过 4。规则见 `评分/通用评分量表.md`。
- 裁判也会错，尤其是事实核查类题目（D15、D16、F 模块、G04）和外语题，请人工抽查。

### 5. 纯手动测试

不想跑脚本也可以：打开 `题库/*.md`，把 `user` 代码块里的内容原样发给模型（多轮题按顺序逐轮发，`system` 块放进系统提示），然后对照"评分要点"和《通用评分量表》打分。

## 推荐的评测流程

1. **先跑一个小样**：`--ids T-A02,T-B08,T-C02,T-I01,T-I02,T-E01,T-J12`，约十几分钟就能看出一个模型的大致水平和 AI 味浓度。
2. **再跑全量**：`--repeat 3`，长上下文模块单独跑并调大 `--max-tokens` / `--timeout`。
3. **先看指标**：`metrics.py` 筛出截断、字数严重不达标、禁词命中、AI 味离群的结果。
4. **再看裁判**：`judge.py` 给出各维度和模块的横向对比。
5. **最后人工细读**：重点读 I 模块（AI 味）、C02 / D21 / J07（盲测）、G01（续航）、E 模块（多轮），这些最能拉开差距，也最容易被自动指标和裁判误判。

**采样参数建议**：创意写作用 temperature 0.7～1.0；法学、病句、阅读理解类可以另跑一组 0.3 对比。同一轮对比中保持参数一致。

## 题目格式（想自己加题时参考）

````markdown
## T-X01｜标题

> 考察：维度1 · 维度2 ｜ 难度：★★★ ｜ 模式：单轮

```system
（可选）系统提示
```

```user
第一轮用户输入。多轮题就写多个 user 块。
可以用 {{file:素材/xxx.txt}} 注入文件，用 {{file:素材/xxx.txt|needle:插入的句子}} 在 55% 处插针。
```

```check
{"target_chars": 1500, "forbid": ["词1", "词2"], "forbid_cats": ["contrast", "aphorism"], "per_turn": true}
```

**评分要点**
- ……
````

`check` 支持的字段：`target_chars`（目标长度）、`forbid`（禁词）、`forbid_cats`（禁用的 AI 味类别：contrast / aphorism / qa_short / body / classic / pseudo_precise / pseudo_deep / residue）、`count_max`（某字最多出现次数）、`per_turn`（多轮题逐轮检查）、`skip_last`（最后一轮是测验，不计入长度检查）、`end_question`（每轮末句必须是问句）、`max_sentences_per_para`（每段最多句数）。

题号必须唯一；改完题库后重新运行 `build_jsonl.py`。

## 说明

- 评分要点里的法条、案号、史实、原著细节是出题时整理的，涉及具体序号和日期的地方已标注"请核实"，正式使用前建议自己再查一遍。
- AI 味模式库是**信号**不是**判决**：人类作家也写"不是……而是"，也会写"慢慢来"。看的是密度、看的是可预测性。用 `--text` 跑人类文本做基线是最可靠的校准方法。
- AI 味相关的资料来源列在 `评分/AI味与活人感词典.md` 末尾。
